Kodi VAAPI/audio port qualification — 2026-10-10

Scope
Two existing YBLOD fixes are ported to the integrated Kodi base:
- Determine VAAPI allocation bit depth/chroma from the decoded software format.
- Acknowledge DISPLAYLOST in audio states without a configured sink; defer
  error-state sink retries until DISPLAYRESET or the bounded retry timeout.
The audio header hunk is adapted to this base's member layout. The historical
alternative DV announcement and single-modeset patches are not imported.

Incremental cross-build/link passes with six workers, eight-CPU container cap

VM runtime
An isolated profile and matching Kodi resources/libplacebo were used, with
the pinned build's libnfs/libplist and installed VM drivers/FFmpeg. The shared
native engine was the tested YBLOD pre4 polynomial-FEL candidate. This is a
mixed test runtime, not qualification of a booted image from this repository.

Renderer logs confirm BT2020_YCC, 10bit, limited range and 10-bit output.
Initial missing-extradata messages were followed by successful codec opening.

successful ALSA initialization. This establishes a playback smoke test, not

The first candidate run with debug overlay enabled looked wrong to the user

Pre-fix and candidate replays with the overlay OFF were both visually

IMPORTANT: the subsequent candidate stop/restart replay was reported glitchy
by the user with the debug overlay still OFF. Therefore candidate DV visual
qualification FAILS intermittently. The initial good replay is insufficient,
and the debug overlay cannot explain all observed failures. The test was
stopped and normal YBLOD restored; the port must remain unmerged pending a
controlled transition investigation. No causal attribution to either patch
versus the mixed runtime or existing adapter is established.

At frame 241 (same clip position), cumulative engine service means:
  pre-fix: 5.774 ms/frame
  patched: 6.002 ms/frame
Both ten-second health windows report zero drops/skips. These short samples
are not a demonstrated speed change and do not measure HDMI/audio latency.
The initial visual problem is associated with different test conditions;
the failed repeat rules out treating overlay removal as a sufficient fix.

Limitations
No independent HDMI capture, audio-listening confirmation, exhaustive error-
state injection or broad live-channel qualification. The transition changes
do not combine the separate refresh-rate and DV-signalling mode changes.
YBLOD already includes these fixes; this port does not require a YBLOD release.

QMS isolation follow-up
The installed YBLOD kernel's i915 qms parameter was enabled during the earlier
tests. With the SAME candidate binary, engine, profile and overlay-off setting,
qms was temporarily disabled before starting the test service. Two playbacks
separated by stop/start were both visually confirmed correct. The user also
reported the TV information overlay showing fixed 24 Hz on the second run.
Kernel display state confirmed requested and adjusted timings both at
296703 kHz / 5500 / 2250 (23.976 Hz); actual pipe clock was 296702 kHz.
Both runs' ten-second health windows reported zero drops/skips. Second-run
cumulative engine processing at about 20 seconds was 5.888 ms/frame.
This supports a QMS/transition interaction in this mixed runtime, not a
proven arithmetic regression or an identified root cause. It does not qualify
QMS-enabled playback. Normal YBLOD and the original qms=Y setting were restored.
